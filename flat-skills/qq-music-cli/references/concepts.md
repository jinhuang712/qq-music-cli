# 整理曲库前要了解的 QQ 音乐概念

动手改之前，先读这一篇。它讲清楚两件事：QQ 音乐怎样组织一个人的曲库，以及 CLI 能做什么、不能做什么。

文中标「实测」的，都在 2026 年 10 月用真实账号验证过；标「未验证」的没有测过。

## 账号与登录

- 用户可以用微信登录（`login_type: wechat`），也可以用 QQ 登录（`login_type: qq`）。
- 账号 ID 是 `uin`，部分读接口还要用加密后的 `euin`。这两个都由 CLI 自己处理，你不需要传。
- 登录 key 的有效期是 3 天（实测）。`qqmusic` 会自动续期；每续一次换一个新 key，有效期重新算 3 天。
- 续期依赖的刷新令牌本身能用多久，未验证。续期失败时，用户需要重新扫码。
- 只有扫码需要用户本人来做。你在后台运行 `qqmusic login --wechat`，弹出的窗口会引导用户完成登录。

## 歌单

| 类型       | 怎么标识                                        | 能否修改       | 说明                                                                            |
| ---------- | ----------------------------------------------- | -------------- | ------------------------------------------------------------------------------- |
| 自建歌单   | `dir_id`（账号内部的小编号）和 `tid`（全局 ID） | 能             | `qqmusic playlists` 列出全部。命令里可以写歌单名、`dir_id` 或 `tid`             |
| 我喜欢     | `dir_id` 为 201                                 | 只能加歌、删歌 | 每个账号有且只有一个，不能删除，也不能改名。「加红心」就是把歌加进这里          |
| 收藏的歌单 | 只有 `tid`                                      | 不能           | 别人的歌单或官方歌单。`qqmusic faved playlists` 列出，`qqmusic show <tid>` 读取 |
| 收藏的专辑 | 专辑的 `id` 或 `mid`                            | 不能           | `qqmusic faved albums`                                                          |

- `dir_id` 只在同一个账号里有意义。分享链接用的是 `tid`，形如 `https://y.qq.com/n/ryqq_v2/playlist/<tid>`。
- 歌单删除后再重建（包括撤销一次删除），会拿到新的 `tid`，旧的分享链接随之失效。
- 服务器允许重名歌单，但 `qqmusic create` 按名字判重：同名歌单已存在时，直接返回那一个。只有用户明确要求时，才加 `--allow-duplicate`。
- 歌单名不能超过 20 个字，简介不能超过 2000 字（实测，这是 y.qq.com 新建和编辑歌单时的上限）。
- 歌单标签（`tags`）是用户在 QQ 音乐里给自建歌单选的标签，比如「R&B」「英语」「安静」。`qqmusic playlists` 和 `export` 都带标签名。`qqmusic` 不能改标签，改名时标签保持不变。
- 歌单列表接口不返回简介（实测：设置简介 30 秒后，列表里仍然为空）。简介要用 `qqmusic show` 读，或者用 `qqmusic playlists --fields +desc`，后者每 10 个歌单多一次请求。
- `listen_count` 是歌单的播放量，也就是所有人播放次数的总和。用户自己的公开歌单，别人也能播放，所以它不等于用户本人的听歌次数。`playlists` 和 `faved playlists` 要用 `--fields +listen_count` 才有，`show` 的 `playlist` 里总是有。
- 收藏和取消收藏别人的歌单或专辑：`qqmusic fav playlist <tid>`、`qqmusic fav album <mid>`，取消用 `unfav`，都能撤销。自己的歌单不能收藏。
- `qqmusic edit --private` 把歌单设成只有用户自己能看到，`--public` 改回所有人可见。改名、改简介、换封面都不会改变公开或私密（实测）。
- `qqmusic edit --cover <图片>` 换封面。图片会居中裁成正方形，边长大于 800 像素的会缩小，处理用的是 macOS 自带的 `sips`。撤销会换回原来的封面。
- 改名用 `qqmusic edit`，歌单的 `tid` 不变，分享链接也不受影响。「我喜欢」等系统歌单（`dir_id` 201 到 206）不能改名。
- 网页版只显示歌单的第一页，`qqmusic show` 和 `export` 则会返回全部歌曲。结果里出现 `complete: false`，说明有歌没读到。
- 「每日30首」「红心雷达」这类官方歌单会自动更新，读到的只是当时的快照。

## 关注

- `qqmusic following` 列出关注的歌手，`qqmusic following users` 列出关注的用户。每条有名字、`mid` 和粉丝数，没有关注时间。
- `qqmusic export` 的结果里也有 `following_singers`。
- 歌手名常带括号里的译名，比如「Jess Glynne (杰斯·格莱茵)」，和歌曲里的歌手名对不上。对比关注的歌手和歌曲时，一律按 `mid` 匹配，不要按名字。

## 歌曲

- 一首歌由数字 `id` 加 `type` 确定。`type` 为 0 是普通单曲，其他类型（长音频、视频）很少见。
- 写操作用 `id` 加 `type`。读操作还接受 14 位的 `mid`，分享链接里出现的就是它：`https://y.qq.com/n/ryqq_v2/songDetail/<mid>`。
- 同一首歌常有好几个版本，各自的 id 都不一样：专辑录音室版、现场版（`(Live)`）、合辑收录版、重制版、`(Explicit)` 版和净化版，还有伴奏（`(伴奏)`）。
  - 比如搜「晴天 周杰伦」，会同时搜到《叶惠美》里的录音室版和好几场演唱会的现场版。
  - 区分版本时，看 `album.name`、`release_date` 和歌名后缀。
  - 除非用户点名要现场版或别的版本，否则优先选原专辑的录音室版。
  - 拿不准哪个是原版时，加 `--fields +comment_count` 比较评论数，原版通常多得多。比如《叶惠美》里的《晴天》有 33 万多条评论，演唱会版约 1 万条（实测）。
- CLI 输出的歌曲字段。「默认」一栏打勾的字段不加 `--fields` 也会输出，其余字段要用 `--fields +字段` 要：

  | 字段                | 默认 | 含义                                                                                                        |
  | ------------------- | ---- | ----------------------------------------------------------------------------------------------------------- |
  | `id`、`type`、`mid` | ✓    | 歌曲标识                                                                                                    |
  | `name`              | ✓    | 显示的歌名                                                                                                  |
  | `artist`            | ✓    | 所有歌手，用斜杠连起来，斜杠前后各一个空格                                                                  |
  | `album`             | ✓    | 专辑，`{id, mid, name}`                                                                                     |
  | `duration`          | ✓    | 时长，单位是秒                                                                                              |
  | `title`             |      | 只在和 `name` 不同时有值，比如多了 `(Explicit)` 后缀                                                        |
  | `subtitle`          |      | 副标题                                                                                                      |
  | `singers`           |      | 歌手列表，每项是 `{id, mid, name}`                                                                          |
  | `release_date`      |      | 发行日期，格式 `YYYY-MM-DD`                                                                                 |
  | `language`、`genre` |      | 语种和流派的数字代码                                                                                        |
  | `vip`               |      | 为 `true` 时，播放这首歌需要 VIP                                                                            |
  | `bpm`               |      | 每分钟节拍数。很多歌没有，实测两个歌单里有值的约占一半到六成                                                |
  | `mv`                |      | MV 的 vid，链接是 `https://y.qq.com/n/ryqq_v2/mv/<vid>`；没有 MV 时为空                                     |
  | `qualities`         |      | 有哪些音质，取值 `320k`、`flac`、`hires`、`dolby`。只认这四种，「臻品母带」「臻品全景声」这类新格式认不出来 |
  | `track_no`          |      | 在专辑里是第几首                                                                                            |
  | `cover`             |      | 专辑封面，300×300                                                                                           |
  | `url`               |      | 歌曲在 QQ 音乐网页上的链接，给用户看歌时用它，不要自己拼                                                    |
  | `comment_count`     |      | 评论总数，可以当作热度参考。每 10 首歌要多发一次请求，几百首歌的歌单要慎用                                  |

- `qqmusic song` 还有 6 个字段，每首歌要多发一次请求，只在要用时才查：`--detail` 加上前 4 个，也可以在 `--fields` 里点名任意一个。

  | 字段            | 含义                    |
  | --------------- | ----------------------- |
  | `genre_name`    | 文字版流派，例如 `Pop`  |
  | `language_name` | 文字版语种，例如 `国语` |
  | `company`       | 唱片公司                |
  | `publish_time`  | 发行时间                |
  | `intro`         | 歌曲简介，很多歌没有    |
  | `trans_name`    | 译名                    |

### 语种和流派代码

代码对应的文字名称，要用 `qqmusic song <歌曲> --detail` 查（看 `language_name` 和 `genre_name` 字段）。下表是抽样查询真实歌曲得到的（实测）。流派名称保持接口原样返回的英文：

| `language` | 语种                 |     | `genre` | 流派              |
| ---------- | -------------------- | --- | ------- | ----------------- |
| 0          | 国语，也可能表示未知 |     | 1       | Pop               |
| 1          | 粤语                 |     | 3       | Jazz              |
| 3          | 日语                 |     | 12      | Other             |
| 4          | 韩语                 |     | 20      | Dance             |
| 5          | 英语                 |     | 21      | Easy Listening    |
| 9          | 纯音乐               |     | 22      | Electronica       |
| 20         | 瑞典语               |     | 23      | Folk              |
| 24         | 越南语               |     | 31      | New Age           |
|            |                      |     | 33      | R&B               |
|            |                      |     | 34      | Rap/Hip Hop       |
|            |                      |     | 36      | Rock              |
|            |                      |     | 37      | Soundtrack        |
|            |                      |     | 50      | Alternative       |
|            |                      |     | 58      | Singer Songwriter |

- `genre` 为 0 表示未知。很多歌根本没有流派信息，华语歌尤其多。
- 遇到表里没有的代码，挑一首样本歌，用 `--detail` 查一下。
- `--detail` 每首歌要多发一次请求。适合抽样，或者每批 50 首左右分批查，不要一次查整个曲库。

## 专辑

- `qqmusic album <专辑 mid>` 输出专辑信息和全部曲目。专辑 mid 可以从歌曲的 `album.mid`、`qqmusic search --type album` 或 `qqmusic faved albums` 拿到。不登录也能查。
- `album` 对象里有：类型（`type`，例如「录音室专辑」）、语种、唱片公司、推荐标签（`labels`，例如「金曲奖获奖」）、获奖记录（`awards`）、编辑推荐语（`rec_text`）和简介（`desc`）。简介可能很长，《叶惠美》的有 2568 个字。
- 专辑的 `genre` 是 QQ 音乐自己标的，有时和直觉不符，比如《叶惠美》标的是 Rap。判断曲风时不要只看它。
- `album` 的输出可以直接接给 `add`：`qqmusic album <mid> --fields id,type | qqmusic add "<歌单名>" --stdin`。

## 搜索

- `qqmusic search` 需要登录。不登录时，所有类型都搜不到结果（实测）。
- `qqmusic match <关键词...>` 搜出每个关键词下的热门公开歌单（默认每个关键词 8 个，用户自己的歌单不算），返回用户曲库里出现在这些歌单里的歌。`hits` 是出现在几个歌单里，`in` 是这首歌现在在用户的哪些歌单里。它也依赖搜索，同样需要登录。
- 公开歌单里常混进不相干的热门歌。`hits` 不小于 2 的比较可信，只出现在一个歌单里的要再判断（实测）。
- 实测：五个 city pop 关键词读了 40 个公开歌单，用时约 20 秒。

## 评论

- `qqmusic comments song|album|playlist <对象>` 读热门评论，加 `--new` 读最新评论，`--limit` 控制条数（默认 20，最多 200）。不登录也能读。
- 结果里的 `total_comments` 是评论总数，和网页上「评论(149)」的数字一致（实测）。`listed` 是这个列表能翻到的条数，热门评论通常只有十几到几十条。
- 每条评论默认给出 `content`、`likes`（点赞数）、`replies`（回复数）和 `time`（发表时间，Unix 秒）。评论者昵称要用 `--fields +user`，只在用户需要时才取。
- `album` 的结果里总会带上专辑的 `comment_count`。
- 个别歌曲或专辑的评论读不到，接口返回错误码 20022（不登录也一样），原因未知。这时 `comment_count` 为 null，`comments` 命令会报错退出。排序或求和前先过滤掉 null。
- CLI 只读评论，不发评论、不点赞、不回复。

## 限制与安全

- 写操作每批 20 首，批与批之间间隔一秒左右，CLI 会自动处理。
- 退出码 4 表示 QQ 音乐觉得请求太频繁（错误码 2001，也就是风控）。停一下，过几分钟再继续就行。具体的阈值未验证。
- 每次写操作都会在 CLI 的数据目录（`~/.local/share/qq-music-cli/runs/`）里记一条 run，`qqmusic undo <run_id>` 能把它撤销：
  - 加的歌会被删掉
  - 删的歌会被加回去
  - 新建的歌单会被删除；只有歌单为空时才删，否则要加 `--force`
  - 删除的歌单会被重建，原来的歌也会加回去
  - 改名、改简介、公开或私密、封面都会改回原样
  - 收藏会被取消，取消的收藏会被加回来
- 撤销后加回的歌，顺序可能和原来不一样（未验证）。
- `add` 会跳过歌单里已有的歌，`remove` 会列出本来就不在歌单里的歌。所以同一条命令执行两次是安全的。

## CLI 暂时做不到的事

- 调整歌单里歌曲的顺序。y.qq.com 网页本身也没有这个功能。
- 关注、取消关注歌手。网页发这个请求时带签名和加密，CLI 不实现这种请求。查看关注列表没有问题。
- 播放、下载音乐，或者读取播放记录。最接近的替代是官方的听歌报告：`qqmusic report`，需要 `QQMUSIC_API_KEY`。
- 发评论、点赞、回复评论。CLI 只能读评论。

用户提出这类需求时，直接说明做不到，再给出能做到的替代办法。
